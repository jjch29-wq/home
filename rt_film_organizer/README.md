# RT 필름 영상화 정리기

OCR은 `더보기 → 선택 사진만 OCR 검사`로 선택한 행만 검사할 수 있습니다. Ctrl·Shift로 여러 장을 선택할 수 있으며, `OCR 분석 (보조 검증)`은 전체 사진을 검사합니다. 두 메뉴 모두 먼저 최대 폭 1,600px의 빠른 검사를 수행하고, 필수 정보가 빠졌거나 평균 신뢰도가 65% 미만일 때 정밀 검사를 이어갑니다. OCR 모델은 앱 실행 중 재사용합니다. 빠른 검사의 인식값도 실제 납마킹과 대조해야 합니다.

고정 카메라로 촬영한 RT 필름 사진을 자르고, 저장된 RT 보고서 또는 납마킹 OCR을 이용해 파일명을 만드는 로컬 앱입니다. 원본 사진과 보고서 데이터는 수정하지 않습니다.

## 실행

VS Code에서 `RT 필름 영상화 정리기 (Run/Debug)`를 선택해 F5를 누르거나 `run_app.bat`을 실행합니다. 현재 PC의 `.venv` 환경을 사용합니다.

## ① 사진과 보고서 불러오기

입력·출력 폴더를 선택하고 `① 사진 불러오기`를 누릅니다. 마지막 폴더는 이 PC에서 기억합니다.

`보고서 순서 배정`은 발행 이력 `home/src/report_apps/ndt_report/data/report_issue_history.json` 또는 `RT_Data_*.json`을 읽습니다. 삭제된 보고서와 다른 검사 종류는 제외하며 저장된 항목 순서를 유지합니다. 항목별 촬영 매수를 확인한 뒤 순서 배정을 실행하세요. 저장된 RT_OR/RT_RE 매수를 사용하고, 없으면 원촬영 3장·보수 0장을 제안합니다. 0장은 제외합니다.

여러 보고서는 배정 창 위의 후보에서 고르고 `보고서 추가`로 작업 목록에 넣습니다. 다른 파일의 보고서는 `다른 이력 / JSON 파일 추가`로 후보를 불러올 수 있습니다. 첫 보고서는 자동 추가되며 동일 보고서 중복 추가는 차단합니다.

`위로`·`아래로`로 작업 순서를 정한 뒤 `전체 목록 순서로 사진 배정`을 누릅니다. 보고서를 선택하면 예상·배정·누락 매수와 첫·마지막 사진 이름이 표시됩니다. 누락을 수정하거나 매수를 바꿀 때는 `이 보고서 시작 사진 번호`를 확인하고 `선택 보고서만 다시 배정`을 사용하세요. 다른 보고서 배정은 유지됩니다. 보고서 간 같은 사진이 겹치면 적용을 차단합니다.

이미 배정한 보고서를 이동하면 사진 연결은 유지되고 최종 항목 순서만 바뀝니다. 사진도 새 목록 순서에 맞춰 다시 연결하려면 전체 배정을 실행하세요. 전체 재배정은 수동 연결을 대체하기 전에 확인하며, `목록에서 제외`는 작업 목록에서만 제거합니다. 모두 확인한 뒤 `전체 배정 적용 후 사진 확인`을 누르면 메인 화면으로 돌아갑니다. 출력은 기존처럼 라인번호별 폴더로 나뉩니다.

누락 사진은 해당 항목을 `누락 / 배정 안 함`으로 바꾸고 이후 사진을 직접 재배정합니다. 중복 배정은 차단하며 배정하지 않은 사진은 결과에서 제외합니다. 보수 또는 3장이 아닌 항목은 메인 화면에서 구간을 직접 선택해야 합니다.

## ② 영역 편집

`적용 대상`을 먼저 선택합니다.

- **전체 사진 (공통)**: 자동 검출·영역 지정·추가 자르기를 공통 영역에 적용합니다. 개별 지정 사진의 영역은 유지합니다.
- **선택 사진 한 장**: 표에서 선택한 사진에만 적용합니다.

`영역 지정`은 불러온 원본 전체에서 다시 선택합니다. `더보기 → 현재 영역에서 더 자르기`는 현재 범위를 기준으로 더 좁힙니다. 저장은 별도 버튼으로 실행하며, 반복 편집도 원본 좌표를 사용해 중간 JPG를 재압축하지 않습니다.

`개별 지정 해제`은 해당 사진의 개별 지정만 해제합니다. `더보기 → 공통 자르기 되돌리기 (최초 지정)`은 이번 작업에서 처음 설정한 공통 영역을 복원합니다. `원본/크롭 보기`는 미리보기만 전환하며 자르기 설정을 바꾸지 않습니다.

표의 `적용 영역`에 공통·개별 상태와 크기를 표시하고, 미리보기 아래에는 원본과 현재 크기를 구분해 표시합니다. 화면 위아래의 어두운 배경은 저장 사진에 포함되지 않습니다. 해상도는 실제 픽셀 수를 표시하며, 확인되지 않은 과업 기준으로 합격·불합격을 판정하지 않습니다. 단순 확대나 선명도·대비 보정은 하지 않습니다.

## ③ 내용 확인

라인번호·JOINT·구간·파일명·적용 영역을 대조합니다. `OCR·보고서 상세`를 켜면 용접사, 구간판정, 순번, OCR 원문과 보고서 상세를 펼칩니다.

OCR은 `더보기 → OCR 분석 (보조 검증)`에서 실행하는 선택 기능입니다. 보고서 배정 상태에서는 배정값을 유지하고 인식값의 불일치를 표시합니다. 미인식은 일치로 간주하지 않습니다. 보수 사진의 구간은 촬영 순서만으로 확정하지 않으며 직접 확인해야 합니다.

보고서 배정이 없으면 OCR의 JOINT 정보를 기준으로 원촬영 3장 구간을 제안합니다. OCR 미실행 상태의 3장 순환은 임시 값입니다. 반드시 실제 납마킹과 비교하세요.

## ④ 결과 저장

- `더보기 → 원본 이름으로 잘라 저장`: 공통·개별 영역으로 자르고 출력 폴더 아래 `일괄자르기`에 원본 이름으로 저장합니다.
- `확인 후 저장`: 검토한 이름으로 라인번호별 하위 폴더에 저장합니다. 기본은 `라인번호/R01(1-2).JPG`이며 라인번호가 없으면 `라인미확인` 폴더를 사용합니다.

파일명은 기본적으로 `R01(1-2).JPG` 형식입니다. 변경하려면 `더보기 → 파일명 설정`을 켜세요. 파일명 치환자는 `{joint}`, `{section}`, `{line}`, `{report}`, `{welder}`, `{seq}`, `{size}`, `{date}`, `{original}`을 사용할 수 있습니다. 기존 파일은 덮어쓰지 않고 번호를 붙입니다. 이름을 적용한 저장은 `영상화_작업기록.csv`에 원본·최종 경로·보고서·개별 자르기 좌표를 기록하며 재저장 시 `_2`, `_3` 등 별도 기록을 남깁니다. 중간 오류가 발생해도 이미 저장된 사진의 기록은 보존합니다. 처리가 끝날 때까지 편집·불러오기는 잠깁니다.

## 작업 이어하기

`작업 저장`은 공통·최초·개별 영역, 보고서 배정, 사진 순서, 편집값과 출력 설정을 `.rtfilm.json`에 보관합니다. `작업 열기`로 복원하세요. 원본 사진 자체는 작업 파일에 포함하지 않으므로 같은 경로에 있어야 합니다. 사진을 다시 불러오면 현재 배정과 영역이 초기화되므로 필요한 작업은 먼저 저장하세요.

## OCR 모델

EasyOCR 모델은 `models` 폴더를 사용하며 필요한 모델이 없으면 최초 OCR 실행 때 내려받을 수 있습니다. 사진과 OCR 정보는 외부로 전송하지 않습니다.
