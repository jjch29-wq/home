# 사업장별 독립 실행 구조

| 사업장 | 수정할 코드 | 기존 실행 파일 |
| --- | --- | --- |
| 중앙지사 | `central/src/app.py`와 같은 폴더의 모듈 | `home/src/한국지역난방 중앙지사.py` |
| 가스공사 | `kogas/src/app.py`와 같은 폴더의 모듈 | `home/src/가스공사 가산~가평.py` |
| 롯데 | `lotte/src/app.py`와 같은 폴더의 모듈 | `home/src/롯데건설 바이오로직스.py` |

기존 실행 파일과 바로가기를 그대로 사용한다. 각 사업장 폴더의 `main.py`로도 실행할 수 있다.
개별 내부 모듈 대신 이 실행기를 사용한다. 설치된 기존 EXE는 이번 소스 변경을 자동 반영하지 않는다.

각 사업장은 `src`(코드·설정·이력), `data`(재고·사진), `resources`(보고서 양식)를 가진다.
기존의 상대 경로 구조를 유지하면서 저장 위치를 사업장 안으로 옮겼다.
화면·계산·보고서 모듈도 독립 복사했으며, 로컬 import는 사업장 전체 경로를 명시한다.
따라서 공통 `home/src/views`, `services` 등을 수정해도 이 세 프로그램에는 자동 반영되지 않는다.
외부 라이브러리와 Python 환경은 여전히 공통이므로 환경 업데이트에는 전체 확인이 필요하다.

## 데이터 이전

이전 시점의 실제 재고 파일(src 우선, 없으면 data), 사업장별 설정·이력, 기존에 공유하던 단가 설정,
양식·서명·공정사진을 복사했다. 원본은 이동·삭제·수정하지 않았다.
중앙지사와 롯데가 공유하던 `config.json`은 같은 초기 내용에서 시작하지만 이후 별도로 저장된다.
롯데 기성 화면과 가스공사·롯데 문서 허브는 각 사업장의 재고를 참조한다.
롯데에는 기존부터 작업/감독일보의 `daily_work_history.json`과 보고서용
`lotte_daily_work_history.json` 두 이력 파일이 있었다. 두 파일을 모두 롯데 전용 폴더에
보존하고 각 화면의 기존 파일 선택을 유지했다. 같은 이름의 중앙지사 파일과는 별개다.
사업장 기록을 추정하여 합치거나 삭제하지 않았다.

이제 운영 데이터는 **각 사업장 폴더 안의 파일**이다. 원래 `home/data`나 `home/src` 파일을
수정해도 새 사업장 파일에 자동 동기화되지 않는다. 백업할 때 사업장 폴더 전체를 포함한다.
사용자가 파일 선택창으로 지정하는 외부 양식·출력 경로는 그대로 선택할 수 있다.

`migration_manifest.json`은 이전 원본·복사본 경로와 SHA-256을 기록한다.
`home/tools/isolate_sites.py`는 일회성 이전 도구이며 대상이 이미 있으면 덮어쓰지 않고 중단한다.
이전 이후 수정된 파일의 해시는 이 초기 기록과 달라지는 것이 정상이다.

## 검증 및 복구

`python home/tests/test_site_isolation.py`는 GUI를 열지 않고 문법, 로컬 import 경계,
실제 설정·재고·이력 경로 선택, 계산 결과, 실행기 연결을 검사한다.
GUI 실행 및 Excel/인쇄 프로그램 연동은 정상 Python 환경에서 별도로 확인해야 한다.

실행기 전환 이전의 세 원본 코드는 `home/archive/site_isolation_originals`에 있다.
복구가 필요하면 먼저 모든 프로그램을 종료하고 **현재 사업장 폴더 전체를 백업**한 다음,
그곳의 해당 원본 코드를 원래 한글 실행 파일 위치로 복사한다.
그러면 기존 공유 모듈·기존 데이터 경로를 다시 사용하므로, 이전 후 새로 입력한 데이터는
자동으로 따라오지 않는다. 사업장 데이터와 원본 데이터를 확인한 후 별도로 복구해야 한다.
사업장 폴더를 먼저 삭제하거나 원본 데이터에 일괄 덮어쓰지 않는다.
