# 중앙지사 24시간 모바일 웹앱 적용 안내

이 묶음은 기존 Google Apps Script 웹앱을 업그레이드하는 배포 소스입니다.
로컬 파일을 바꾸는 것만으로 현재 운영 웹앱이 갱신되지는 않습니다.

## 구현 범위

- 입력 / 작업 목록 / 기록 조회 / 공정 현황 / 재고 / 더보기 메뉴
- PC '작업/감독일보' 탭의 '1. 작업 물량 및 누계 현황'과 실시간 연동 (PAUT, RT, MT, PT 전 규격 및 공정률 % 모바일 대시보드)
- 기준일자(검사일) 선택 시 PC 일보 누계 히스토리와 당일 현장 입력 실시간 작업 물량을 합산하여 전일누계, 금일작업, 총누계, 공정률(%), 불량수/불량률 실시간 계산
- 중앙 관리 업체 목록, 작업자 32명, 차량·이동수단 16개 기준자료
- PAUT·RT·UT·MT·PT 입력, 작업자별 일비 저장, 선택 자재의 재고 품목 ID 자동 연결
- 검사방법 변경 시 재고 품목·소모품·주 장비·보조장비 목록을 PC 분류 기준으로 함께 필터링
- PAUT 선택 시 보조장비를 `스캐너 → 탐촉자 → 웻지 → 기타 보조장비` 순서로 입력하고 기존 보조장비 필드에 함께 저장
- 관련 소모품이 있는 검사방법에서만 자재명 입력을 표시하며, PAUT·UT 과거 기록의 기존 자재값은 수정 시 보존
- 동일 자재가 여러 창고에 있을 때만 출고 기준 창고를 선택하며, 예외 품목은 `고급 설정 · 재고 수동 연결`에서 지정
- 최대 30건의 작업 대기 목록과 기기별 임시저장
- 접속 시 저장된 임시 입력을 확인창 없이 자동 복원하고 화면 상태로 안내
- 저장 실패 시 목록 유지, 부분 성공 건만 제거, 요청 ID로 재전송 중복 방지
- 기간·업체·방법·검색어별 기록 조회 및 50건 단위 더 보기
- 게시 시점의 PC 재고 조회: 자재·모델·창고 검색, 입고·사용·잔량 표시

재고는 PC에서 생성한 기준자료이며 실시간 잔량이 아닙니다.
모바일 입력 뒤 PC 동기화·재집계 후 기준자료를 다시 생성하고 배포해야 새 잔량이 표시됩니다.
현재 재고 목록은 PC 표시 기준에 맞춰 비활성·빈 ID 품목을 제외합니다.

다중 차량 입력, 사진 첨부, 입출고 처리, 기성·예산 편집은 이번 범위에 포함하지 않습니다.

분류 미확인 품목은 검사 입력의 기본 선택 목록에서 제외합니다.
해당 검사방법의 주 장비가 등록되지 않았다면 다른 방법의 장비 대신 '등록된 관련 주 장비 없음'으로 표시합니다.
과거 기록을 명시적으로 불러올 때만 목록 밖의 기존 저장값을 보존하며, 검사방법을 바꾸면 관련 없는 선택값은 해제합니다.

## 적용 전

1. 현재 사용 중인 중앙지사 Apps Script 프로젝트와 연결된 시트를 확인합니다. 경인 프로젝트에 적용하지 않습니다.
2. 기존 Code.gs와 index.html을 별도로 복사하고, 연결된 스프레드시트도 사본을 만들어 보관합니다.
3. 기존 배포 버전·URL·접근 권한을 기록합니다. 재고 조회가 추가되므로 현재 URL의 접근 대상이 적절한지 확인합니다.

## Code.gs 한 파일로 적용 (화면 포함 합본)

압축 묶음의 **Code.gs**에는 Workspace.gs·Reference.gs와 전체 모바일 HTML 화면까지 포함돼 있습니다.
별도의 index 또는 MobileShell HTML 파일을 찾지 않고 합본 안의 화면을 사용합니다.
index.html은 검토용으로 함께 제공하지만 실제 적용에는 Code.gs 한 파일만 교체하면 됩니다.
Workspace.gs·Reference.gs·MobileShell.html을 중복 추가하지 않습니다.

1. 기존 프로젝트의 Code.gs를 묶음의 Code.gs 전체 내용으로 교체합니다.
2. 기존 index HTML 파일은 그대로 두어도 됩니다. 합본 Code.gs가 내장 화면을 사용합니다.
3. 저장 후 테스트 배포에서 입력·대기 목록·조회·재고 메뉴를 확인합니다.
4. 검증용 시트에서 저장, 같은 요청 재시도, 수정, 삭제를 확인합니다. 운영 자료에 시험 기록을 넣지 않습니다.
5. 승인한 접근 범위로 기존 배포를 새 버전에 연결합니다. 권한 확대나 Google 승인 화면은 사용자가 확인합니다.
6. 기존 URL에서 새 메뉴를 확인하고, PC 동기화 후 작업 1건의 날짜·수량·일비가 일치하는지 확인합니다.

첫 시트 접근 시 필요한 누락 열과 ClientRequestID·ClientRequestHash 열만 기존 시트 끝에 추가합니다.
기존 행을 초기화하지 않습니다. 앱 삭제 기능은 실제 시트 행을 지우므로 미리보기에서는 운영 삭제를 시험하지 않습니다.

## 기준자료 갱신과 재포장

프로젝트 루트에서 사용 중인 안정 재고 파일을 명시해 실행합니다.

```powershell
.venv/Scripts/python.exe tools/prepare_central_mobile_reference.py --inventory "사용 중인 중앙지사 Material_Inventory.xlsx 경로"
.venv/Scripts/python.exe tools/package_central_mobile.py
```

결과는 outputs/central-mobile-gas/ 아래에 생성됩니다.
원본 설정·엑셀은 읽기만 하며, 재생성된 묶음을 다시 배포해야 Google 웹앱에 반영됩니다.

## 검증 상태와 남은 확인

GAS 서버 모의검사와 클라이언트 대기 목록 검사는 계정·네트워크 없이 수행합니다.
로컬 미리보기는 실제 클라우드에 저장하지 않습니다.
Windows 브라우저 자동 제어가 URL을 확인하지 못해 휴대폰 폭 화면 검증과 실제 계정 배포는 아직 완료하지 못했습니다.
따라서 소스 검사 통과를 실제 Google 배포·저장 검증 완료로 간주하지 않습니다.

## 되돌리기

문제가 있으면 기존 배포 버전으로 연결을 되돌립니다.
시트에 새로 추가된 식별자 열은 기존 기록과 함께 보존합니다. 되돌릴 때 시트 행이나 열을 일괄 삭제하지 않습니다.
