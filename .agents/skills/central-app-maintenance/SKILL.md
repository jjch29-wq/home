# 중앙지사 앱 유지보수

## 작업 시작

- 현재 작업 디렉터리와 저장소 루트를 확인한다. 기본 프로젝트 위치는 `C:/Users/jjch2/Desktop/PMI`이지만 실제 열린 저장소를 우선한다.
- 현재 체크아웃의 적용 가능한 `AGENTS.md`, 특히 `home/src/site_apps/AGENTS.md`를 읽는다. 브랜치별 코드와 규칙을 실제 파일에서 확인한다.
- `git branch --show-current`와 `git status --short`로 브랜치와 기존 변경을 확인한다. 브랜치 이름을 `중앙지사-개발` 하나로 제한하지 않는다. 새 기능 브랜치에서도 중앙지사 코드를 확인해 작업할 수 있다.
- 요청 대상과 현재 체크아웃이 맞는지 확인한다. 명백히 다른 사업장 작업용 브랜치이거나 중앙지사 코드가 없으면 수정 전에 불일치를 설명하고 필요한 대상만 확인한다. 기존 변경을 없애거나 요청 없이 브랜치를 전환하지 않는다.
- 이 스킬은 유지보수 절차이며 앱 수정 요청 자체를 대신하지 않는다. 사용자가 질문만 하면 확인 결과를 설명하고, 수정 요청이 있으면 실행한다.

## 코드 위치와 경계

다음은 탐색 시작점이다. 경로와 연결 함수는 현재 체크아웃에서 다시 확인하며 줄 번호를 고정하지 않는다.

- 실행기: `home/src/site_apps/central/main.py`
- 호환 실행기: `home/src/한국지역난방 중앙지사.py`
- 앱 본체: `home/src/site_apps/central/src/app.py`
- 화면·이벤트: 같은 사업장의 `src/views/`, `src/controllers/`
- 계산·출력: 같은 사업장의 `src/services/` 및 해당 기능 모듈
- 검증: `home/tests/test_central_*.py`, `home/tests/test_site_isolation.py`

업무 기능은 중앙지사 구현에서 수정한다. 다른 사업장에 같은 변경을 자동 복제하거나, 중복 코드라는 이유로 사업장 간 import·공통화를 하지 않는다. 격리 세부 기준은 현재 저장소의 `AGENTS.md`를 따른다.

## 수정과 데이터 보존

- 화면 문구에서 연결된 이벤트·저장·조회·출력 경로를 필요한 만큼 추적한다. 기존 동작을 바꾸는 경우 사용자가 체감하는 변경을 설명한다.
- 재고·작업 이력·사진·설정과 사용자의 미커밋 변경을 보존한다. 검증을 위해 운영 엑셀이나 설정 파일을 초기화하지 않는다. 데이터 변환이 요청되면 원본을 보존하고 대상과 결과를 명확히 한다.
- 설정 문제는 저장 호출만 보고 해결됐다고 판단하지 않는다. 로드 순서, 초기 배치·숨겨진 탭의 임시값, 일반 저장의 덮어쓰기, 복원 시점을 함께 확인한다.
- 날짜 이동은 날짜 칸만 바꾸지 말고 필요한 목록·메모·선택 상태를 함께 갱신한다. 작성 중인 내용을 교체할 때는 기존 확인 절차를 재사용한다. 같은 날짜 재선택과 취소 시 보존도 고려한다.
- 메모·조회 연결은 필요한 날짜와 현장 범위를 유지하고, 목록 미리보기와 상세 원문을 구분한다.

## 검증과 실행

- 사용 가능한 프로젝트 Python을 확인한다. 이 작업 환경에서는 `.venv/Scripts/python.exe`가 사용된 적이 있다. `python`이나 `py`가 동작한다고 가정하지 않는다.
- 변경한 Python 파일의 구문을 확인하고, 기능의 실제 위험에 맞는 기존 검증을 실행한다. 저장·복원, 취소 시 입력 보존, 현장 간 혼합 같은 회귀를 검증한다. 단순 문구·간격 변경에 구현을 그대로 따라 하는 테스트를 만들지 않는다.
- 사업장 코드 변경 후 `home/tests/test_site_isolation.py`를 실행한다. 추가 검증은 해당 기능과 관련된 범위로 선택한다.
- GUI 검증이 필요하면 앱의 실행 환경을 확인한다. 테스트 목적으로 실제 업무 데이터 저장을 일으키지 않는다. Tk 환경 누락 등으로 창을 확인할 수 없으면 로직 검증과 실제 화면 확인을 구분해 보고한다.
- 테스트 통과를 실제 앱 재실행 확인으로 표현하지 않는다. 실행 중인 앱에 소스 수정이 자동 반영된다고 가정하지 않는다. EXE 실행이면 소스 변경만으로 기존 EXE가 갱신되지 않음을 안내한다.

## 마무리와 Git

- 수정된 동작, 수행한 검증, 실제 화면·재실행 확인 여부, 남은 제약을 짧게 보고한다.
- 커밋·푸시는 사용자의 요청 범위에 따라 진행한다. 스킬 사용 자체를 커밋·푸시 승인으로 해석하지 않는다. 이미 승인된 범위는 재확인하지 않는다.
- 커밋 시 이번 요청 파일과 기존 변경을 구분해 선택적으로 스테이징한다. 푸시 전 대상 브랜치·원격을 확인하고, 완료 시 브랜치·커밋을 보고한다.
